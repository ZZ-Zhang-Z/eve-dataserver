# EVE Online 市场结构速览（面向金融建模）

> 目的：为本地套利分析工具提供一份"市场微观结构"基础说明，便于后续做价差、深度、费用与资金占用建模。

## 1. 总体特征

| 维度 | EVE 市场 | 传统金融市场 |
| --- | --- | --- |
| 经济体 | 单一服务器（Tranquility）、单一货币 ISK、无跨市场汇率 | 多交易所、多币种 |
| 交易所 | 分散在 region × station（每个星系/站点一个独立订单簿） | 集中撮合 |
| 交易方式 | 纯限价单（买/卖挂单），无做市商义务、无竞价撮合连续流 | 集合竞价 + 连续撮合 |
| 做空/杠杆 | **不存在**，也无期货、期权等衍生品 | 普遍存在 |
| 套利本质 | **多头库存型空间套利**（低买 → 运输 → 高卖） | 含空头/期限/统计套利 |

结论：EVE 的"套利"更接近**实物商品贸易 + 库存周转**，而非金融无风险套利。任何模型都必须显式计入运输与库存成本。

## 2. 经济体量与集中度

- 全服统一市场，交易高度集中于 **Jita（region 10000002）**。
- Jita 4-4 站是事实上的"主市场"，价格发现与流动性最强；其他区域流动性可能低 1~2 个数量级。
- 本工具当前采集的快照规模（实测）：
  - Jita 单快照卖单 + 买单合计约 **40.5 万条订单**
  - 全量采集耗时约 **35.7s**（拉取 ~18s + 写库 ~16s）

流动性极度不均 → 模型需要按 (type_id, location) 粒度评估深度，不能用"全市场均价"。

## 3. 订单簿结构（数据可建模维度）

ESI `GET /markets/{region_id}/orders` 返回的是**限价订单簿**，每条订单字段：

- `order_id`：全局唯一，**订单生命周期内稳定**（改价/改量不变；撤单重挂才换新 id）
- `type_id`：物品类型
- `location_id`：站点/建筑
- `price` / `volume_remain` / `volume_total`
- `is_buy_order`：买 / 卖
- `issued` / `duration` / `range`（买单可达范围）

由这些字段可以直接计算：

- 最佳买卖价差（best bid / best ask）与 mid price
- 各价位挂单量 → **盘口深度曲线（depth）**
- 订单失衡 OBI（Order Book Imbalance）
- 分位加权均价 VWAP / 成交量加权成本
- 改单事件（本项目已落盘）→ 价格调整速度、挂单撤换频率

## 4. 摩擦成本（建模必须显式计入）

| 成本项 | 说明 | 典型量级 |
| --- | --- | --- |
| 经纪费 Broker Fee | 下单/改单时按比例收取，依技能与声望 | 约 1.0%~3.0% |
| 交易税 Sales Tax | 成交时按比例收取 | 约 1.0%~4.5% |
| 改单费 Relist Fee | 修改订单价格·数量时收取 | 与经纪费同规则 |
| 运输时间 | 星系间跳跃（跳数 × 时间），影响库存周转 | 分钟~小时级 |
| 运输风险 | 低安全区可能被击毁（货损 = 100%） | 视航线而定 |
| 资金占用 | 往返期间 ISK 被占用，无利息收益 | 机会成本 |

**净收益公式（单笔往返）**：

```
净收益 = 卖出收入 × (1 - 经纪费 - 交易税)
       - 买入支出 × (1 + 经纪费)
       - 运输与货损期望成本
       - 资金占用机会成本
```

## 5. 数据可得性与时效

| 数据源 | 接口 | 内容 | 时效 |
| --- | --- | --- | --- |
| 实时订单簿 | `GET /markets/{region_id}/orders` | 当前全部挂单（公开、免认证） | 服务端缓存约 5 分钟 |
| 成交历史 | `GET /markets/{region_id}/history` | 按 type_id 的日线 OHLCV | 日级 |
| 静态数据 | 官方 SDE | 物品/星系/星域等 | 版本级 |

本项目当前落地情况：

- 订单簿：`market_orders` 表（Jita 约 40.5 万行）
- 改单追踪：每 30 分钟一次快照 diff（`market_order_events` / `market_order_snapshots` / `market_orders_staging`），保留窗口 72 小时
- 静态数据：SDE 全量导入（items 等）

## 6. 建模约束与建议

- **无做空 / 无杠杆 / 无衍生品** → 只能做现货库存套利，收益 = 价差 × 可成交量 - 全链路成本。
- **流动性分层** → 先按 `(type_id, location)` 统计深度与日成交，再筛"可吃量 × 价差 > 成本"的标的。
- **强事件驱动** → 版本更新、战争、资源改版会剧烈改变供需，历史参数需滚动窗口。
- **数据频率有限** → 订单簿约 5 分钟缓存、历史仅日线，高频策略不可行，适合中低频（小时~日级）套利。
- **容量约束** → 单个订单簿短期内可承接的成交量有限，模型需给出"可执行收益 vs 名义收益"。

## 7. 可落地的下一步（模型化方向）

1. **价差筛选矩阵**：按 (type_id × location) 计算买卖价差率与可吃深度，输出候选清单。
2. **净收益模型**：把经纪费、交易税、运输时间/风险、资金占用纳入收益函数。
3. **改单行为指标**：用已落盘的 `market_order_events` 计算挂单撤换率、价格调整速度，作为流动性/波动代理变量。
4. **库存周转优化**：在资金约束下求最大化周转收益的资产组合。
